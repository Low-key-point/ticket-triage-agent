# 银行客服工单分流智能体验收说明

版本：V3待验收版。日期：2026-11-07。本轮先验收程序，用户确认通过后再更新Word报告和课程提交包。旧报告是基础分类版，尚未包含本轮大模型实验。

## 1. 先启动

在PowerShell进入项目目录后运行：

```powershell
cd D:\myagent\ticket-triage-agent
.\.venv\Scripts\python.exe -m triage.web
```

打开 http://127.0.0.1:8765/ 。启动窗口保持运行。也可使用scripts/start.ps1。若端口已被本项目占用，直接打开页面；修改Python代码后需要重启本项目服务再刷新。不要同时运行多个版本。

## 2. 配置大模型

1. 左侧进入“大模型设置”。
2. 将自己的DeepSeek API密钥填入密码输入框，模型默认deepseek-flash。
3. 点击“保存到本次服务内存”。保存后密码框清空；此时只表示配置已保存，尚未验证密钥可用。
4. 点击“测试实际连接（调用API）”。成功应显示“DeepSeek实际连接成功”、模型和Token用量。
5. 不需要提供GitHub或DeepSeek账号密码，也不要把密钥发在聊天里。密钥在[DeepSeek开放平台](https://platform.deepseek.com/api_keys)自行创建。

接口固定为DeepSeek官方域名。密钥仅存在服务端内存，8小时后过期；重启服务后清除。关闭网页不等于立即清除配置，可以点击“清除密钥配置”。清除不取消已经发出的请求。浏览器刷新后连接测试标记可能需要重新确认。

测试连接、摘要和生成工单都会调用外部服务，可能消耗账户额度；没有自动充值或无限重试。每类生成1—10条，一批最多14类，每类一次请求。建议先选一个类别、2条样本。分类、复核和本机训练不消耗API额度。

## 3. 验收基础分流

在“处理工单”输入以下虚构内容，编号可不填：

| 输入 | 预期观察 |
| --- | --- |
| 我想查询一下银行账户的余额 | 建议查询余额、账户查询队列；当前基础模型可自动完成分流 |
| 我的银行卡被偷了，请冻结我的账户 | 进入等待人工复核；展示敏感请求原因及人工专席建议 |
| 请推荐一只值得购买的股票 | 进入等待人工复核，不应被当作已支持的投资服务 |

查看前三候选、概率、演示知识说明和执行轨迹。概率只是估计，系统只做模拟分流，不办理实际银行业务。

## 4. 验收“其他”人工归档

1. 提交“请推荐一只值得购买的股票”。确认它先进入“等待人工复核”，最终意图尚为空。
2. 打开“复核工作台”，在该工单行点击“复核 →”；或从处理结果点击“前往复核工作台”。在工作台复核详情的最终意图下拉框选择“其他 · 其他工单队列（仅人工）”。
3. 填写“投资建议不属于目前14类业务”，点击“确认并结束工单”。
4. 预期最终意图为“其他”，最终队列为“其他工单队列”，保留原分类建议、复核理由与轨迹。
5. 到“复核工作台”，筛选“其他（人工归档）”，能找到该记录；列表和导出均显示最终分类与队列。

“其他”不是第15个自动预测标签。自动分类、LLM生成和候选训练都不能直接把工单归入“其他”。只有待复核工单经过人工选择与理由确认才能归档。已结束工单不能重复复核。

## 5. 验收复核摘要

1. 配置并测试DeepSeek后，提交“我的银行卡被偷了，请冻结我的账户”。
2. 点击结果中的“生成 / 重新生成摘要（调用API）”。也可进入“复核工作台”，打开该工单后生成摘要并对照客户咨询。
3. 预期看到核心诉求、原文依据、待补充信息、复核建议、模型、时间及Token用量。所有引用必须能在工单原文中找到。
4. 对照原文检查摘要有无新增金额、日期、损失事实或已处理结论。发现不实内容不要采纳，记录问题反馈。
5. 摘要生成后，最终类别、队列和复核状态不会因此自动改变；仍需进入“复核工作台”，由人工选择最终意图、填写理由并确认。处理工单页不提供人工确认表单。

可以勾选“待复核时自动请求大模型摘要”，之后新提交的待复核工单会请求摘要。默认不勾选；已存在摘要的重复工单不会因该选项自动再次生成。

程序会验证JSON结构和引用子串，不能自动证明摘要语义完全正确。LLM失败或引用无依据时提示错误，保留工单状态和已有摘要。刷新后从复核工作台查看工单，成功保存的摘要仍在。

## 6. 验收训练增强

1. 进入“数据增强与模拟”。用途选“训练集数据增强”。
2. 先选“查询余额”，数量2，场景“普通咨询”或“口语与错别字”。点击“开始生成（调用API）”。
3. 查看类别进度、实际返回样本、失败提示。请求通常需要数秒至约90秒；多类别依次生成，全部14类可能需要较长时间。关闭页面后后台任务可能仍继续，刷新可查看已保存的批次。
4. 通过检查的记录标为“待人工审核”。重复、过近似、疑似号码或邮箱等记录标为“自动隔离”，不能批准。
5. 逐条核对类别是否正确、是否只包含一个诉求、表达是否自然、是否含隐私或无依据业务政策。符合才点击“保留”，不符合点“拒绝”。不要为了凑数量全选通过。
6. 点击“下载本批次JSON”，检查合成来源、模型、提示版本、训练种子编号、Token用量、审核状态及过滤原因。
7. 有至少一条保留的训练候选后，点击“用已审核样本训练候选模型”。预期显示基础与候选在同一74条验证集上的准确率和宏F1，以及训练条数。

候选实验只使用本批次已保留的训练增强样本。训练开始时冻结审核快照，之后修改审核状态不会回改已完成的实验，重新训练会生成新的比较结果并覆盖本批次上一候选文件。候选文件位于data/synthetic/，基础模型仍是models/model.joblib。

效果可能提高、持平或下降，都属于需要保留的真实结果。不要将验证集结果写成测试结果，不用原95条测试集反复挑选增强方案。当前没有自动启用候选模型的功能。

## 7. 验收模拟工单

1. 用途改为“模拟工单演示（不用于训练）”。
2. 可选择多诉求、范围外、信息不足、敏感请求等场景，先生成1—2条。
3. 生成后点击“填入工单页试用”，再点击“分析并创建工单”。填入动作本身不会创建工单。
4. 观察分流和复核结果，必要时人工选择“其他”。模拟样本不会自动归入任何最终类别，也不能用于候选训练。

场景标签是给生成器的要求，不代表已被独立人工验证。生成文本可能没有严格遵循场景，验收时要检查实际内容。

## 8. 故障与隐私检查

| 情况 | 预期 |
| --- | --- |
| 未填密钥请求摘要、连接测试或生成 | 明确提示先配置；本地分类继续可用 |
| 密钥无效、余额不足、限流、超时 | 给出中文错误说明，不回显密钥或供应商原始错误体，不自动无限重试 |
| 模型返回截断JSON、无原文依据的引用 | 不保存本次摘要；生成异常类别记录失败，不假装成功 |
| 生成过程中重复点击开始或训练 | 拒绝并发任务，提示等待 |
| 服务重启打断生成或训练 | 已保存记录保留，任务标为中断失败；需要手动重试，不自动继续计费 |
| 未审核或模拟样本尝试训练 | 拒绝进入候选训练 |
| 自动预测试图输出“其他” | 作为非法模型输出回退到待复核，不能直接归档 |

仅使用公开或虚构内容。脱敏不是完整隐私保护；调用摘要时脱敏文本会发送到DeepSeek，增强时会发送少量公开训练样例。密钥、工单、生成数据、模型文件均未上传GitHub。
